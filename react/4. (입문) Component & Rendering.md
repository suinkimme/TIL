## Component & Rendering

### 1. Component

- 컴푸넌트는 리액트의 핵심 빌딩 블록 중 하나다.
- 리액트에서 개발할 모든 애플리케이션은 컴포넌트 조각으로 구성된다.
- 컴포넌트는 UI 구축 작업을 훨씬 쉽게 만들어준다.
- 리액트 컴포넌트는 **선언체**이다.

> 선언체란? 어떻게 동작할지 직점 명령(절차)하는 게 아니라, 결과(구조)를 선언하는 것을 말한다.

#### <명령형>

```javascript
const div = document.createElement('div');
div.textContent = "Hello, React!";
document.body.appendChild(div);
```
- "어떤 순서로 만들 것인가"를 직접 하나하나 작성함
- DOM을 조작하는 코드를 직접 사용함

#### <선언형>

```javascript
const MyComponent = () => {
  return <div>Hello, React!</div>;
};
```

- 컴포넌트가 어떤 모습일지 선언한 것
- 실제로 화면에 렌더링될 때는 리액트가 알아서 해석 후 DOM을 조작함

### 2. Rendering

- 화면에 처음으로 컴포넌트를 그리는 과정

### 3. Re-Rendering

- 이미 렌더링된 컴포넌트가 `state`, `props`의 변화로 다시 렌더링되는 과정
- 여러 상태가 변경됐다면 리액트는 이를 큐 자료구조에 넣어 순서로 관리한다.

### 렌더링 과정 (렌더링, 리렌더링 포함)

1. Trigger

    - 트리거가 발생하는 경우
      - Rendering
        - 앱이 처음 화면에 나타날 때
      - Re-Rendering
        - `useState()`값이 변경됨
        - 부모 컴포넌트로에서 받은 `props`가 변경됨
        - `useReducer()` 상태가 변경됨
        - `context` 값이 변경됨

2. Render
    - Rendering
        - 전체 Virtual DOM을 생성함
        - `useEffect` 초기 실행이 포함됨
    - Re-Rendering
      - 기존 Virtual DOM과 비교해서 변경된 부분만 업데이트
      - `useEffect`는 의존성 배열에 따라 실행될 수도 있고 안 될 수도 있음
3. Commit
    - Virtual DOM에서 변경된 부분을 실제 DOM에 적용하는 단계
