## 문제

크래프톤 정글 코딩테스트 사전 학습 자료에 나온대로 포트포워딩을 진행했지만, 실제로는 포트포워딩이 되지 않았다.

## 상황

제공된 사전 학슴 자료는 다음과 같다.

```shell
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j REDIRECT --to-port 5000
```

AWS 보안 그룹 인바운드 규칙에 문제는 없고, 포트포워딩이 제대로 실행되었음을 명령어를 통해 여러 번 확인했다.

```shell
sudo iptables -t nat -L --line-numbers

num  target     prot opt source               destination
1    REDIRECT   tcp  --  anywhere             anywhere             tcp dpt:http redir ports 5000
```

## 해결

[이 블로그](https://promisingmoon.tistory.com/190)를 통해 해결하게 되었다. 블로그에서 말하고자 하는 것은 아래와 같다.

- iptables: ip관리하는 테이블, 방화벽을 설정하는 명령어
- -t nat: NAT 테이블을 선택
- -A PREROUTING: -A는 새로운 정책을 추가, -A PREROUTING은 라우팅 전에 결정되는 규칙을 추가
- -i eth0: eth0인 입력 네트워크 인터페이스와 매칭
- -p tcp: TCP 프로토콜과 매칭
- --dport 80: 목적지 포트가 80에 대해 매칭
- -j REDIRECT: -j는 jump로, 매칭되는 패킷을 어떻게 처리할지 결정, REDIRECT는 리디렉션
- -to-port 5000: 패킷을 5000으로 리디렉션

eth0 네트워크 인터페이스로 들어오는 패킷 중, 목적지 포트가 80인 TCP 패킷을 5000 포트로 리디렉션 해주는 명령어라고 한다.
<br>
해당 블로그의 필자는 인터페이스를 바꿔주니 해결되었다고한다. 그래서 나도 변경해보았다.

블로그의 필자가 제공하는 **버전 및 아키텍처 별 네트워크 인터페이스**다.

|우분투 버전|아키텍처|네트워크 인터페이스|
|------|-----|-----|
|우분투 24.04|ARM|ens5|
|-|X86|enX0|
|우분투 22.04|ARM|ens5|
|-|X86|eth0|

즉, 위의 명령어에서 eth0 부분을 현재 서비스의 스펙에 맞게 변경해주면 정상적으로 동작 된다!

### 서버 아키텍쳐 확인 명령어

```shell
uname -m # 예: x86_64
```

나는 우분투 24.04를 사용하고 있기에 `enX0`로 변경해 정사적으로 포트포워딩이 적용되었다!
